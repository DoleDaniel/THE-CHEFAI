# PERMANENT RESOLVED BOTTLENECK REGISTRY

This file is a hard constraint layer for the agent. The rules below have been officially debugged and must never be broken or reverted during code generations.

## [FIXED] Bug 001: Lazy Keyword Snippet Matching
- **Issue:** Inputting 'beef' returned 'Chicken Suya' because it matched descriptive text strings instead of structural recipe properties.
- **Permanent Fix Rule:** All ingredient matching must be structured via strict boolean logic filters. If a primary protein constraint (e.g., beef) is requested and the target item is alternative (e.g., chicken), the card must be dropped from the output list.

## [FIXED] Bug 002: Hardcoded Fallback Arrays
- **Issue:** Changing inputs like 'buns, ground beef' still returned a static menu loop of 'moimoi, fried rice, egusi'.
- **Permanent Fix Rule:** The custom ingredients query array must wipe all static cache fallbacks. The output generation stream must change dynamically to match the input state.

## [FIXED] Bug 003: Over-Filtering Resulting in 0 Suggested
- **Issue:** Inputting breakfast sets like 'oats, milk, strawberries' returned 0 results because of a lack of flexible mapping thresholds.
- **Permanent Fix Rule:** Activate the "Pantry Flex" protocol. If core items match but non-essential elements (salt, sugar) are missing, classify it as a valid match and indicate the missing staple via the chatbot interface.

## [FIXED] Bug 004: YouTube API Origin Mismatch & Watchdog Timeout
- **Issue:** Under restricted networks or DNS resolution failure, YouTube embeds failed silently or took 25 seconds to show the fallback card. Cross-origin messages also threw noisy browser errors in the console.
- **Permanent Fix Rule:**
  1. Shorten the YouTube API initialization and loading watchdog timeouts to 6 seconds to ensure instant fallback card loading.
  2. Implement global window error and unhandled promise rejection interceptors to capture and suppress cross-origin `postMessage` or `DOMWindow` target origin errors.

## [FIXED] Bug 005: Bean Batter / Slurry Recipe Matching Mismatch
- **Issue:** Inputting processed physical states like "bean batter" failed to match core ingredients like "black-eyed beans" due to preparation adjectives remaining in the query, causing unrelated dishes (like fish stew) to sort higher.
- **Permanent Fix Rule:**
  1. Strip preparation terms like "batter", "slurry", "soaked", "wet-ground", and "peeled" inside `cleanIngredientWord`.
  2. Implement a dedicated Beans / Cowpea equivalence group in `chefSemanticMatch` to ensure cross-cultural matching of bean batter/slurries with raw bean ingredients.

## [FIXED] Bug 006: Rice and Beans Over-Association & Dynamic Content Leaks
- **Issue:** Recommending bean-only recipes (such as Feijoada or MoinMoin) when a user inputted rice (without beans) was confusing. Also, dynamic YouTube fallback suggestions leaked ingredients outside the user's logged class profile (e.g. suggesting beef stew for a rice-only query).
- **Permanent Fix Rule:**
  1. If rice is in the user's query and beans are not, exclude any bean-based recipes unless the recipe itself explicitly contains rice.
  2. Implement the classification filters (grain, legume, tuber, meat) and base protein validations on dynamic YouTube video suggestions to prevent showing dishes with outside primary ingredients.

## [FIXED] Bug 007: Scrolled Past Video Fails to Resume & Warning Log Bypasses
- **Issue:** Scrolling past a video correctly paused it, but scrolling back to the same video failed to resume playback. Also, some cross-origin `postMessage` exceptions were passed as objects instead of strings, bypassing the console warn/error filters and cluttering the browser console.
- **Permanent Fix Rule:**
  1. Expand the `feedVideoObserver` IntersectionObserver to call `playVideo()` when a video container returns to intersecting viewport state.
  2. Upgrade the warning and error console filters to extract string content from object keys like `msg.message`, `msg.reason`, or `msg.stack` before matching keywords.

## [FIXED] Bug 008: YouTube API No-Cookie Domain Origin Conflict
- **Issue:** Using `youtube-nocookie.com` with the programmatic `new YT.Player` API triggered persistent `postMessage` target origin mismatch logs because the YouTube Widget API internally references `youtube.com`, causing cross-domain communication warnings.
- **Permanent Fix Rule:** Use `youtube.com` instead of `youtube-nocookie.com` for both `getCleanEmbedUrl` and `YT.Player` host parameters to align origins.

## [FIXED] Bug 009: Unmatched Unique Base Staples Leakage
- **Issue:** Suggesting recipes (like Egusi Soup, Okra Soup, Oatmeal) requiring unique base starches or seeds that the user did not input just because minor elements (beef, oil, salt) matched. Dynamic video suggestions also leaked these unmatched staple recipes.
- **Permanent Fix Rule:**
  1. Define a list of `uniqueBaseStaples` representing unique starch/seed/legume/base ingredients that define dishes (e.g. egusi, okra, oats, rice, cornmeal, pasta).
  2. Exclude any local database recipe or dynamic YouTube video suggestion if it requires any unique base staple that the user did not input.
  3. Expand `getIngredientCulinaryClass` and `getPrimaryCulinaryClass` regex categories to capture oats and cornmeal.

## [FIXED] Bug 010: Undefined Procedure & Ingredients Properties in Suggestions
- **Issue:** Suggestion output cards and modal details sections were missing food details. `procedure` was mapped as `recipe.procedure` instead of `localRecipe.procedure`, resulting in empty procedures. Similarly, `ingredients` was missing on the suggestion objects, leaving the cross-cultural substitutions panel empty.
- **Permanent Fix Rule:**
  1. Map `procedure` to `localRecipe.procedure` and `ingredients` to `localRecipe.ingredients` for database recipes.
  2. For dynamic web suggestions, set `procedure` from `localDbMatch.procedure || localDbMatch.procedures` and set `ingredients` from `finalIngredients`.

## [FIXED] Bug 011: ReferenceError for scaleIngredientAmount
- **Issue:** Clicking "Details & Steps" button threw `ReferenceError: scaleIngredientAmount is not defined` because the scaling helper was referenced but never defined in `app.js`.
- **Permanent Fix Rule:** Implement a robust `scaleIngredientAmount` function in `app.js` using the existing `evalFraction` parser to scale and re-format recipe amounts when portion servings change.

## [FIXED] Bug 012: Local Dialect Ingredient Recognition for Search & Matching
- **Issue:** Inputting local dialect ingredient names (e.g. `garri` for cassava flakes/eba, `ukwu` for ugu/pumpkin leaves, `cryfish` for crayfish) caused empty or irrelevant search results on YouTube/Google because the APIs did not recognize the specific local names.
- **Permanent Fix Rule:**
  1. Add local dialect equivalence mappings (e.g. tuber, leafy green, egusi, locust beans, pepper groups) in `chefSemanticMatch` so the local database matches them accurately.
  2. Implement `getStandardizedIngredientsForSearch` to translate local dialect terms to standard search keywords (e.g. `garri` to `garri eba cassava`) before executing YouTube search queries.
  3. Classify local dialect starches (`garri`, `eba`) correctly under the `tuber` category in `getIngredientCulinaryClass` and `getPrimaryCulinaryClass`.

## [FIXED] Bug 013: Cuisine Filter Bypass & Loose Ingredient Matches in Web Video Suggestions
- **Issue:** Selecting a cuisine filter (e.g. Nigerian) did not restrict dynamic YouTube suggestions to that cuisine, resulting in suggestions from other cultures (e.g. Brazilian). Also, dynamic YouTube matched database recipes bypassed all core quality controls, recommending dishes with missing unique staples (like Yam Porridge when potato was inputted).
- **Permanent Fix Rule:**
  1. Define a centralized `isRecipeValidForCuisineAndIngredients` validator function in `app.js` to enforce all constraints (cuisine/culture, base protein validation, rice & beans check, primary class matching, and unique base staples checks).
  2. Invoke `isRecipeValidForCuisineAndIngredients` inside both the local database matching loop and the dynamic YouTube suggestion loop (for both matched database recipes and parsed web suggestions).
  3. Ensure that parsed YouTube suggestions explicitly mention the selected cuisine in the title, description, or channel name if a cuisine filter is active.

## [FIXED] Bug 014: Duplicate & Mismatched Static Recipe Image Assets
- **Issue:** Some static recipe images were mismatched or placeholders (e.g. `Brazilian Fish Moqueca`, `Brazilian Coxinha`, and `Mexican Enchiladas` were all sharing the same image of dumplings, and `Nigerian Suya Grilled Chicken` had a cartoon pot outline on the left).
- **Permanent Fix Rule:** All static database recipes must map to high-quality, professional, and correct food images that correspond to the actual dish. Mismatched duplicate asset links (like gyoza dumplings matching to fish stew) are strictly prohibited.

## [FIXED] Bug 015: Ad Network Resource Resolution Failures (doubleclick/googleads)
- **Issue:** When embedding YouTube video players, standard YouTube URLs loaded tracking cookies and ad requests from doubleclick/googleads, causing browser console resource loading errors (`net::ERR_NAME_NOT_RESOLVED`) when adblockers or offline DNS configurations block these ad network domains.
- **Permanent Fix Rule:**
  1. Always use `youtube-nocookie.com` in `getCleanEmbedUrl` to load embedded frames in privacy-friendly mode, preventing cookie-based ad networks from being requested.
  2. Set the `host` parameter inside `new YT.Player` options to `https://www.youtube-nocookie.com` to maintain origin alignment, resolving both origin warnings and ad network network failures.

## [FIXED] Bug 016: Major Ingredient Leakage in Suggested Output Results
- **Issue:** Suggesting recipes (e.g. Brazilian Cheese Bread requiring tapioca starch/cheese) for user inputs that only match a single minor ingredient (e.g. egg) while missing the major base starches or proteins (e.g. yam), leading to loose, impossible-to-cook formulations.
- **Permanent Fix Rule:**
  1. Define a list of allowed pantry items, seasonings, and common bases (e.g. onions, garlic, oil, tomatoes, water, salt, spices) that are permitted to be missing from the user's inputs.
  2. Ensure that any major, defining recipe core ingredient (e.g. tapioca starch, cheese, flour, grains, whole proteins) that is not in the allowed pantry/seasonings list must be matched by the user's inputs or their flexible substitutes.
  3. Classify `tapioca` as a tuber inside class and primary class regular expressions to correctly track starches.

## [FIXED] Bug 017: Mismatched Procedure Headers & Empty Web Video Ingredients Checklist
- **Issue:** The details modal for YouTube search suggestion videos incorrectly renamed the "Cultural Story" section to "Step-by-Step Procedure" and displayed the description there, while leaving the actual procedure list at the bottom. Additionally, some YouTube videos did not have an "Ingredients:" section in their description, leading to empty parsed ingredient checklists (e.g., only "pastries" for a sausage egg pastry).
- **Permanent Fix Rule:**
  1. Always select the correct modal procedure header by using `#modal-procedure-list` previousElementSibling to prevent selector conflicts.
  2. Implement `extractIngredientsFromTitleAndDescription` to scan the combined title and description text against a dictionary of known major ingredients (e.g., sausage, egg, cheese, chicken, beef, etc.) if the standard description parser returns no results.

## [FIXED] Bug 018: Empty Step-by-Step Procedure Lists in Web Video Details Modals
- **Issue:** Web video details modals had completely empty lists under the `Step-by-Step Procedure` section due to an overly restrictive check `if (recipe.isYoutubeVideo || !recipe.procedure)` that blocked procedure list rendering entirely for YouTube search suggestions.
- **Permanent Fix Rule:**
  1. Always populate the step-by-step procedure list if `recipe.procedure` contains instructions.
  2. Fall back to a stylized, helpful instruction ("Watch the live video demonstration above to see the full cooking procedures...") in the list if the procedure array is empty, ensuring the modal is never left blank.
  3. Implement a bullet-point parser inside `extractIngredientsFromDescription` to extract ingredient list items from video descriptions even if an explicit header is missing, and expand the dictionary of known major ingredients to prevent fallback mismatches.

## [FIXED] Bug 019: Mismatched Dish Types Listed as Ingredients (e.g., "soup")
- **Issue:** The search engine matched the word "soup" from the title/description and generated it as a checklist ingredient (e.g. `[ ] soup` and `[ ] mutton` for a mutton soup query), which is incorrect because "soup" is a dish type, not a standalone ingredient.
- **Permanent Fix Rule:** Never include general dish categories, course types, or basic liquids/staples (e.g., `soup`, `stew`, `sauce`, `broth`, `water`, `salt`, `oil`) inside the parser's `knownDictionary`. The dictionary must only contain concrete, purchasable recipe components (e.g. mutton, chicken, beef, fish, onions, garlic).

## [FIXED] Bug 020: Lazy Web Video Recipe Suggestion Details (Ingredients/Procedures)
- **Issue:** For search results with incomplete description info (like mutton soup), opening the details modal only showed basic fallbacks (e.g., just the typed ingredient and a generic watch video instruction) instead of detailed procedures and full ingredient breakdowns.
- **Permanent Fix Rule:**
  1. Frontend `openRecipeModal` must intercept web suggestion clicks that are not yet fully researched, displaying a loading spinner inside the modal card content.
  2. Perform an asynchronous backend fetch to `/api/research` to dynamically query detailed ingredients, full instructions, and scaled nutritional value.
  3. Backend `/api/research` must utilize the Gemini API (via search grounding) or a smart local keyword-based recipe generator to build 100% complete, realistic, human-made ingredient checklists and detailed procedures (e.g. detailed mutton soup steps).

## [FIXED] Bug 021: Card Ingredient Advertisement & Unnecessary Servings Control & Copy-Pasted Search Ingredients
- **Issue:** The suggestion cards advertised ingredient counts and visualizations directly on the preview section, cluttering the UI. Additionally, different suggestion cards on the same query copy-pasted the user's shelf inputs as fallback ingredients, making suggestions identical. Finally, the servings control panel inside the details modal was unnecessary.
- **Permanent Fix Rule:**
  1. Hide the servings control panel in the details modal by setting `.servings-control` display to `none !important`.
  2. Remove all matching/missing ingredient checklists and ingredient count indicators from suggestion card previews, showing only the Title, Description, and the live "Details & Steps" button.
  3. Do not fall back to user shelf ingredients if parsed ingredients are empty. Unresearched web suggestions must keep their ingredients array empty until the user clicks "Details & Steps" and triggers the specific dynamic backend research route.

## [FIXED] Bug 022: Generic Fallback Ingredients & Missing Verification Reference Sources
- **Issue:** If Gemini API key is missing or when using the local recipe fallback generator, the modal showed generic water/salt ingredients and simple steps. Furthermore, there was no way to display source reference links to verify where the recipe information was fetched.
- **Permanent Fix Rule:**
  1. Add a dedicated "Verified Reference Sources" section in the details modal (`#modal-sources-section` and `#modal-sources-list`).
  2. Modify backend `/api/research` to enable **Google Search Grounding** in the Gemini API configuration (`tools: [{ googleSearch: {} }]`).
  3. Parse the returned `groundingMetadata.groundingChunks` sources and output them as clickable verification links. For local fallbacks, dynamically attach a Google Search link for the video title for full transparency.

## [FIXED] Bug 023: False Exclusions of Local Cuisines (Jollof Rice, Stews) under Cuisine and Ingredient Filters
- **Issue:** Selecting preferred cuisines (e.g. Nigerian) with matching ingredients (rice, beef) returned zero suggestions because:
  1. The Base Protein Validation Constraint incorrectly flagged recipes using "chicken stock" or "beef broth/bouillon" as protein conflicts, locking out dishes if the user didn't have both meats.
  2. The Classification Filter blocked recipes requiring allowed missing pantry ingredients (like tomatoes, peppers, onions in Jollof Rice) if the user didn't log those specific vegetables in their kitchen shelf.
- **Permanent Fix Rule:**
  1. Do not flag recipes as protein conflicts based on seasoning liquids or bouillon stocks (ignore "stock", "broth", "cube", "seasoning" in isChickenRecipe/isBeefRecipe checks).
  2. Skip class checks for allowed missing pantry/seasoning items inside the Classification Filter loop to prevent blocking valid recipes.
